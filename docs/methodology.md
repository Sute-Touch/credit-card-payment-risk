# Методология

## Задача

Проект оценивает риск неплатежа действующих клиентов кредитных карт
и формирует ранжирование для ограниченного ручного контроля.

Задача не включает автоматическое одобрение или отказ в кредите,
оценку мошенничества или принятие кредитного решения.

## Данные

Источник: UCI Machine Learning Repository —
Default of Credit Card Clients.

Исходный набор содержит 30 000 наблюдений, 23 признака и целевую
переменную `default payment next month`.

Целевая переменная:

- `1` — неплатёж в следующем месяце;
- `0` — отсутствие неплатежа.

Доля событий в исходном наборе — 22,12%.

## Контроль качества

На этапе первичной проверки выполнены:

- проверка количества строк и столбцов;
- проверка уникальности и пропусков ID;
- проверка полных дубликатов строк;
- проверка пропусков в исходных столбцах;
- анализ категорий SEX, EDUCATION, MARRIAGE и платёжных статусов;
- анализ диапазонов числовых признаков;
- подсчёт отрицательных значений в суммах счетов и платежей.

Пропуски, повторяющиеся ID и полные дубликаты строк не обнаружены.

## Разделение данных

Набор разделён стратифицированно по целевой переменной:

- train — 24 000 клиентов, 5 309 событий;
- test — 6 000 клиентов, 1 327 событий.

Доля событий в обеих частях составляет 22,12%.

Разделение выполнено до исследовательского анализа связей признаков
с целевой переменной. Тестовая выборка использовалась один раз
после фиксации модели и протокола проверки.

## Признаки версии v0

Использованы исходные признаки и три производных признака:

- `TOTAL_BILL_AMT` — сумма счетов за шесть месяцев;
- `TOTAL_PAY_AMT` — сумма платежей за шесть месяцев;
- `NUM_DELINQ` — количество месяцев с положительным кодом
  платёжного статуса.

Всего модель использует 26 признаков.

Категориальные признаки:

- SEX;
- EDUCATION;
- MARRIAGE;
- PAY_0;
- PAY_2–PAY_6.

Числовые признаки:

- LIMIT_BAL;
- AGE;
- BILL_AMT1–BILL_AMT6;
- PAY_AMT1–PAY_AMT6;
- TOTAL_BILL_AMT;
- TOTAL_PAY_AMT;
- NUM_DELINQ.

## Обработка признаков

Числовые признаки масштабируются с помощью StandardScaler.

Категориальные признаки кодируются методом OneHotEncoder
с параметром `handle_unknown="ignore"`.

Обработка выполняется внутри Pipeline и ColumnTransformer.
Параметры масштабирования и кодирования определяются только
на обучающей части каждого фолда кросс-валидации.

## Модель

Используется логистическая регрессия:

- C = 1.0;
- max_iter = 2000;
- solver = lbfgs.

Искусственная балансировка классов не применялась.

## Сравнение с baseline

Baseline — правило по статусу погашения PAY_0.

Клиенты ранжируются по убыванию PAY_0. При равных значениях
используется возрастание ID.

Это техническое правило воспроизводимости, а не дополнительный
риск-сигнал.

## Метрики

Для каждого лимита ручной проверки рассчитываются:

- количество клиентов в отборе;
- количество событий в отборе;
- доля событий в отборе;
- recall — доля всех событий, попавших в отбор;
- lift — отношение доли событий в отборе к средней доле событий.

Сценарии:

- top-10% клиентов;
- top-20% клиентов.

## Кросс-валидация

Использована стратифицированная 5-fold кросс-валидация
на train.csv.

В каждом фолде модель обучается на четырёх частях и оценивается
на пятой. Для каждого фолда создаётся независимая копия пайплайна
через sklearn.base.clone.

## Финальная проверка

Выбранная модель v0 была обучена на всех 24 000 клиентах train.csv
и один раз оценена на 6 000 клиентах test.csv.

После просмотра тестовых результатов модель, признаки,
гиперпараметры и правила отбора не изменялись.
